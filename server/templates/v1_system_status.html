Server wiederherstellen

Hier bereitest du einen älteren Serverstand zur Wiederherstellung vor. Der laufende Server wird erst durch die anschließende Umschaltung im Synology Container Manager ersetzt.

Wiederherstellungsstatus wird geladen …

Nach der Umschaltung fehlen Änderungen nach diesem Backupdatum. Vorher lokale, noch nicht synchronisierte Arbeiten auf den Handys sichern. Im Portal erneut mit dem Passwort aus dem Backup anmelden.

Vor jedem Update ein Vollbackup erstellen und das dazugehörige Serverpaket bzw. Container-Image sowie Compose und .env geschützt aufbewahren. Neue Vollbackups enthalten einen Programm- und Schemafingerabdruck. Beim Update-Rückweg muss der passende Programmstand laufen; ein Datenbackup allein installiert keine alte Software.

2. Zuerst wird automatisch ein zusätzliches Sicherheitsvollbackup erstellt. Danach werden Datenbank und Dateien im getrennten Ziel wiederhergestellt und geprüft. Der bisherige Serverbestand bleibt erhalten.

Einmalige Einrichtung: die leeren Ordner restore-target-database-v1 und restore-target-storage-v1 in File Station anlegen; getrennte Ziel-Datenbank und Zielspeicher im Worker konfigurieren und freigeben. Anleitung: server/checks/OPS_RESTORE_003.md. Ein bereits belegtes Ziel wird nicht überschrieben.

Zuerst Vollbackup wählen

3. Kontrolliert umschalten

Das Ziel ist vorbereitet. Der laufende Server verwendet weiterhin den bisherigen Bestand.

  1. Wartungszeit vereinbaren. Aktuelle Compose-Konfiguration und .env als Rückweg sichern; laufende Aufträge abschließen lassen.
  2. Im Container Manager API, Worker und Monitor stoppen. Beide Datenbanken und ihre Datenordner behalten.
  3. Die vorbereitete docker-compose.synology-recovery.v1.yml mit den bestehenden Einstellungen verwenden. Die unten angezeigte Wiederherstellungs-ID zusätzlich in .env setzen. Individuelle Anpassungen der bisherigen Compose-Datei übernehmen.
  4. Projekt mit dieser Konfiguration neu erstellen/starten. Datenbank und Speicher werden gemeinsam auf das geprüfte Ziel umgeschaltet. „Neu starten“ allein übernimmt keine geänderte Konfiguration.

      
Rückweg: API, Worker und Monitor wieder stoppen und die gesicherte bisherige Compose-Konfiguration verwenden. Der alte Bestand wurde nicht überschrieben. Änderungen, die bereits im wiederhergestellten Ziel entstanden sind, werden dabei nicht automatisch übernommen.
